# C4 Architecture — OpenSpec-Graph

A right-sized C4 model for `planlint`, a single-process Python CLI that grafts
an OpenSpec governance discipline onto a cloned repository and enforces it
mechanically. The goal is not autonomous agents — it is deterministic,
auditable rules that turn review prose into CI gates.

## 1. Context (System Context)

```text
                   ┌───────────────┐
   contributor ──▶ │  planlint    │ ──▶ pass/fail exit code + JSON report
  (local / CI)     │  CLI + rules  │
                   └───────┬───────┘
                           │ reads
                  ┌────────▼────────┐
                  │  target repo    │
                  │  openspec/ tree │
                  │  + Makefile     │
                  └─────────────────┘
```

**`planlint`** applies a spec discipline to a cloned repository. It reads the
target's `openspec/` tree and detected conventions (Makefile targets, coverage
floor locator, spec dialect), evaluates a fixed rule engine, and emits a
pass/fail result plus a dependency graph. It is invoked locally by contributors
and in CI as a hard gate.

## 2. Container

```text
┌──────────────────────────────────────────────────────────┐
│  openspec-graph  (single Python package, zero runtime deps)│
│                                                            │
│  ┌──────────┐   ┌────────┐   ┌────────┐   ┌───────────┐   │
│  │  cli.py  │──▶│ detect │──▶│ parse  │──▶│  rules    │   │
│  │  + log   │   │ profile│   │ spec   │   │  engine   │   │
│  └────┬─────┘   └────────┘   └────────┘   └─────┬─────┘   │
│       │                                         │          │
│       │  ┌──────────┐   ┌────────┐               │          │
│       └─▶│ scaffold │   │ graph  │◀──────────────┘          │
│          │  init/new│   │ export │                          │
│          └──────────┘   └────────┘                          │
└──────────────────────────────────────────────────────────┘
        ▲                                  ▲
        │ pip install -e ".[dev]"           │ make pre-pr / CI
   contributor                        GitHub Actions
```

One container: a dependency-free Python package (`openspec_graph`) plus a
`tools/` directory of CI gate scripts (coverage floors, secret scan, graph
diff, no-hardcoded-threshold check). Dev dependencies (pytest, ruff, mypy) are
optional extras, never required at runtime.

## 3. Component

| Component | Responsibility | Key types |
|---|---|---|
| `cli.py` | Argparse verbs, exit codes, logging setup | `main`, `cmd_*` |
| `detect.py` | Read the target repo's conventions | `StackProfile`, `profile` |
| `parse.py` | Facade over the parser submodules (below) | `ParsedSpec`, `Requirement`, `Criterion` |
| `rules.py` | Facade over the rule submodules (below); 16 deterministic rules + waiver handling | `Rule`, `Finding`, `evaluate` |
| `scaffold.py` | Write `openspec/` tree + change packages | `plan_init`, `plan_change` |
| `graph.py` | Pure projection of `validate` to a graph | `build_graph` |
| `log.py` | Stderr-only debug logging | `configure`, `level_from` |
| `tools/*` | CI gates: coverage, secrets, diff, thresholds | standalone scripts |

**Data flow:** `detect.profile` → `parse.parse_spec` (per file) →
`rules.evaluate` → `Finding[]`. The graph is a pure projection of the same
`detect` + `parse` + `rules.evaluate` calls, so `broken_links` always equals
the finding count (AC-GR-4) — they cannot disagree by construction.

## 4. Code (Module map)

Post-`decompose-god-files` (PR #4): the four largest modules were split into
focused submodules behind a stable facade, so external imports (`cli.py`,
tests, `__init__.py`'s public re-exports) are unaffected — only the internal
layout changed.

```text
openspec_graph/
├── __init__.py             # public API re-exports
├── cli.py                  # argparse verbs + logging; exit 0/1/2 contract
├── detect.py                # StackProfile: languages, make_targets, dialect, invariants
├── log.py                   # configure(): stderr handler, level from -v / env var
├── graph.py                 # build_graph(): nodes/edges/broken_links, pure projection
├── parse.py                 # facade: spec.md → ParsedSpec (re-exports the four below)
│   ├── parse_model.py         # Criterion / Requirement / ParsedSpec dataclasses
│   ├── parse_semantics.py     # shared regex grammar; non-success, hard-threshold, waiver detection
│   ├── parse_harness.py       # "harness" dialect parser (R-/C- + AC-<AREA>-n)
│   └── parse_upstream.py      # "upstream" dialect parser (### Requirement / #### Scenario)
├── rules.py                 # facade: RULES = GENERIC + HARNESS + UPSTREAM, evaluate() (re-exports the four below)
│   ├── rule_types.py          # Finding / Rule dataclasses, ERROR/WARN/INFO
│   ├── rules_generic.py       # G001–G005 (dialect-agnostic)
│   ├── rules_harness.py       # H001–H006
│   └── rules_upstream.py      # U001–U005
├── scaffold.py               # facade: plan_init/plan_change → WritePlan → apply
└── scaffold_templates.py    # pure string templates for generated docs
```

### Invariants (load-bearing, not aspirational)

- **`broken_links == len(validate findings)`** — the graph is a pure projection
  of `rules.evaluate`; the two can never disagree.
- **Logging never reaches stdout** — `log.py` attaches a stderr handler and
  disables propagation, so `--json` output stays parseable.
- **No hard-coded thresholds** — coverage floors live in `pyproject.toml`;
  the Makefile and workflow only invoke scripts that read them (rule G003).
